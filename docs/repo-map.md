# Pharmacy Scout Repo Map

## Stack

- Frontend: TanStack Start, React 19, TypeScript, Tailwind CSS v4, shadcn/ui
- Data/auth: Supabase (`ulsbnhufczwzrqzolqql`)
- Mapping: Leaflet, React Leaflet, `react-leaflet-cluster`
- Routing/data fetching: TanStack Router, TanStack Query
- Build/runtime: Vite + Nitro/Cloudflare module target

## App structure

- `src/routes/index.tsx`
  - Public map shell at `/`
  - Fetches `pharmacy_premises_geo` directly from Supabase on the client
  - Owns map mode, search, layer toggles, filter state, selected pharmacy, and auth sheet
- `src/components/map/*`
  - `top-bar.tsx`: search, mode switch, account/saved actions
  - `left-panel.tsx`: filters and mode-specific stubs
  - `map-view.tsx`: clustered Leaflet marker layer
  - `right-dossier.tsx`: pharmacy drawer/dossier
  - `layer-menu.tsx`: layer toggles and placeholder coverage list
  - `auth-sheet.tsx`: inline auth modal
- `src/routes/app.*`
  - Signed-in secondary screens for acquisition pipeline and data-source transparency
- `src/lib/*.functions.ts`
  - TanStack Start server functions for orgs, businesses, premises, and source records
- `src/integrations/supabase/*`
  - Client and auth middleware generated by Lovable/Supabase integration

## Database structure today

- Shared/public discovery:
  - `source_records`
  - `pharmacy_premises`
  - `pharmacy_premises_geo` view
  - `pbs_approvals`
- Private/org-scoped:
  - `organisations`
  - `organisation_members`
  - `profiles`
  - `pharmacy_businesses`
  - `candidate_sites`
  - `opportunities`

## Current live state

- Public site shell is implemented and matches the repo build.
- The remote Supabase project currently exposes about 65 geocoded public discovery rows, not the target 900+ statewide dataset.
- Marker clustering is already implemented.
- Acquisition, greenfield, and relocation are mostly UI scaffolds.
- Nearby commercial signals are placeholders only.
- There is no real statewide importer, reconciliation pipeline, pharmacy notes timeline, or IM attachment flow yet.
